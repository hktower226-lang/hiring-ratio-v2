- `../index.html`: 외부 JSON을 읽어 화면과 집계를 만드는 정적 HTML입니다. 데이터 사본을 내장하지 않습니다.
- 두 번째·세 번째 시트는 이번 구현에 포함하지 않았습니다.

## 데이터 수정과 자동 반영

`sheet1.json`만 수정하면 됩니다. HTML을 함께 수정하거나 빌드할 필요가 없습니다. 웹서버에서 JSON이 갱신되면 화면의 ‘데이터 새로고침’, 페이지 새로고침, 화면 복귀 또는 화면을 보고 있는 동안 1분 주기의 자동 확인으로 최신 데이터가 반영됩니다. GitHub Pages에서는 GitHub의 배포가 완료된 뒤 반영됩니다.

메뉴는 전체 → 월별 → 지부별 → 임대사별 순서이며 전체가 첫 화면입니다. 월별 선택 목록은 한노 대수·비율과 민노 비율, 지부별 목록은 한노·민노 비율, 임대사별 목록은 한노 대수·비율만 표시합니다. 임대사 집계 기준은 `rental`입니다. 한 업체의 모든 월·현장 기록을 합칩니다.

임대사 한노 비율이 40% 이상이면 ‘우호업체’, 30% 이하이면 ‘비협조업체’로 자동 표시합니다. 30% 초과 40% 미만은 표시하지 않습니다. 경계 판정은 반올림 전 실제 비율을 사용합니다.

검색창은 모든 메뉴의 상단에 있으며 현장명·원청사·임대사로 선택 목록과 현장 목록을 검색합니다. 표시된 합계·비율·업체 분류는 검색 결과가 아닌 해당 월·지부·임대사의 전체 기록 기준입니다.

잘못된 JSON이 감지되거나 갱신에 실패하면 마지막으로 정상 로드한 데이터를 유지하고 안내합니다. 처음 접속했을 때 데이터를 불러오지 못하면 재시도 안내가 나옵니다. 데이터는 브라우저에 영구 저장하지 않습니다.

## JSON 형식

기존 필드 구조를 유지하세요. `months`에 표시할 월(1~12)을 넣고, `records` 배열에서 현장 기록을 추가·수정·삭제합니다. `id`는 기록별로 중복되지 않게 유지하고, `month`는 `months`에 포함되어야 합니다. `total`과 각 `counts` 값은 0 이상의 정수입니다. `categories`는 기존 순서와 이름을 유지하세요. `branch`, `rental`, `contractor`, `site`, `note`는 문자열이며 비고가 없으면 빈 문자열을 사용합니다. `year`를 변경하면 화면 연도도 바뀝니다.

## 집계 기준

`total`은 원본 총대수, `counts`는 소속별 원본 수치입니다. 비율은 `counts / total * 100`으로 계산하며 소수점 첫째 자리까지 표시합니다. 모든 집계는 월·임대사별 행을 별도 기록으로 더합니다. 현장 이름이 같아도 임의로 중복 제거하지 않습니다. 화면의 건수는 고유 현장 수가 아닌 엑셀 기록 수입니다.

전체: 총대수 243대, 한노 73, 민노 97, 섬유 9, 연합 6, 직원 31, 미정 28.

3월 시화MTV 지하주차장의 총대수는 3, 소속 합계는 4이며 원본 비고는 ‘1대에 2명이 타고있음’입니다. 따라서 전체 소속 합계도 244로 총대수보다 1 큽니다. 수치를 임의로 보정하지 않았으며 해당 기록이 포함된 집계에는 안내가 나옵니다. 비율 합계가 100%를 초과할 수 있습니다. 구성 막대는 소속 합계 안에서의 상대적 구성이며, 총대수 기준의 실제 비율은 각 숫자를 확인하세요.

## 실행

HTML과 JSON을 같은 웹서버에서 제공해야 합니다. HTML 파일을 직접 열면 브라우저 보안 정책 때문에 외부 JSON을 읽을 수 없습니다. 설치·빌드는 필요하지 않습니다. GitHub Pages 게시 방법은 루트의 `DEPLOY.md`에 있습니다.
